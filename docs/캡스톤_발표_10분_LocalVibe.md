## 1. 프로젝트 소개

### 슬라이드에 넣을 내용

- **서비스명:** LocalVibe  
- **한 줄 정의:** 전국 관광·로컬 장소 데이터를 모아, **자연어 검색**과 **AI 여행 플래너**로 탐색·일정을 돕는 웹 플랫폼  
- **핵심 키워드:** `#관광공공데이터` `#의미검색` `#RAG` `#여행플래너` `#React` `#FastAPI`

### 발표 포인트

- “지도 앱 + 블로그 검색”을 한 화면·한 대화 흐름으로 묶은 **통합 탐색·계획 경험**을 목표로 했다고 소개.

---

## 2. 기획 배경·문제 정의

### 문제 (Pain Point)

| 문제 | 구체적 상황 |
|------|-------------|
| **정보 분산** | 관광 공공 API, 블로그, 지도 앱이 따로 놀아 한 번에 비교·탐색하기 어려움 |
| **키워드 검색 한계** | “여수 감성 카페”, “부산 2박 친구 여행”처럼 **의도·분위기**가 들어간 질의에 약함 |
| **일정 설계 부담** | 후보는 많은데 **일차·동선·순서**를 직접 정리해야 해 피로도가 큼 |

### 해결 방향

1. **신뢰 가능한 POI 마스터** — 한국관광공사 등 공공 데이터 기반 `places` 통합  
2. **의미 기반 검색** — 벡터 유사도 + 지역·트렌드 가중 재정렬  
3. **대화형 플래너** — LLM이 기간·지역·취향을 받아 **로드맵(일정표)**까지 제안

---

## 3. 핵심 가치·차별점

### 사용자 가치

- **탐색:** 갤러리에서 질문 한 줄로 “숨은 로컬 스팟” 후보 확인  
- **계획:** 플래너 채팅으로 N박 M일 일정·장소를 채우고 드래그로 순서 조정  
- **보관:** 로그인 후 스크랩·여행 저장, 문의하기로 피드백

### 차별점 (심사·질문 대비)

| 항목 | LocalVibe |
|------|-----------|
| 데이터 | **공공 관광 POI** 중심 (KTO 메타·주소·좌표) |
| 검색 | 키워드 일치 + **임베딩 의미 검색** 하이브리드 |
| 일정 | 단순 리스트가 아니라 **일차·오전/오후·동선** 로드맵 UI |
| 확장 | 크롤 텍스트·GPT 아티클·비교/지도 시각화 API |

## 4. 주요 기능 ① — 갤러리

### 기능 요약

- **통합 헤더·사이드바:** 갤러리 / 플래너 / 마이페이지, 지역 트리(시·도 → 시·군)  
- **의미 검색:** 상단 검색창 → `/api/search` 벡터 검색 → **3열×5행(15곳)** 카드 그리드  
- **지역 필터:** 사이드바에서 지역 클릭 시 해당 지역 **전체 장소** 스크롤 탐색 (검색과 UX 분리)  
- **장소 카드:** 썸네일, 스크랩(♥), 여행 담기(+), 상세 모달(요약·아티클·이미지)

### 데모 멘트 (약 1분 30초)

1. “부산 2박 감성 카페” 검색 → 15곳 추천  
2. 사이드바 **여수** 클릭 → 지역 전체 목록  
3. 카드 클릭 → 상세·아티큈(블로그+GPT 구조화 본문)

### 기술 포인트 (한 줄)

- 검색 결과 `imageUrl` 보강, `/api/regions/feed`로 초기 피드, sessionStorage로 검색 상태 유지

## 5. 주요 기능 ② — 여행 플래너 (핵심)

### 기능 요약

| 구성 | 설명 |
|------|------|
| **로드맵(좌)** | 일차별 장소 리스트, 드래그·삭제, 장소 검색 추가 |
| **AI 채팅(우)** | `/api/chat/trip` — 기간·지역·취향 반영, 일정 생성·수정·교체 |
| **장소 비교** | 채팅에서 “비교해줘” → 비교 모달(표·카드·AI 한눈에 요약) |
| **지도·갤러리 시각화** | `/api/visual` — 지도 마커, 이미지 갤러리 |
| **저장** | 마이페이지 여행에 일정 저장 (`user_trips`) |
| **새 채팅** | 채팅·로드맵·일정 **전체 초기화** (확인 후) |
| **로그인 유지** | 로그인 계정별 localStorage에 **채팅·일정** 복원 |

### 대화 예시 (시연 스크립트)

```
사용자: "부산 2박 3일, 친구랑 맛집·카페 위주, 절은 빼고"
→ AI: 일정 제안 + 로드맵 6~9곳 자동 배치
사용자: "2일차만 여유롭게 바꿔줘" / "○○ 말고 △△로 바꿔줘"
→ refine / replace 액션으로 로드맵 갱신
```

### 발표에서 강조할 핵심

- **“검색으로 찾고 → 플래너로 정리한다”** 는 사용자 여정이 끊기지 않음 (갤러리에서 여행 담기)  
- 백엔드가 `recommendedRegionIds` + `schedule`(일차·슬롯)을 내려주고, 프론트가 로드맵에 반영

## 6. 주요 기능 ③ — 개인화·문의

### 로그인·마이페이지

- Google OAuth (`/api/auth/google`)  
- **스크랩** (`user_scraps`), **여행 일정** 생성·장소 추가 (`user_trips`, `user_trip_places`)  
- 플래너에서 만든 로드맵 → “마이페이지에 저장”

### 문의하기

- 모달이 아닌 **전용 페이지** (헤더·사이드바 포함 레이아웃)  
- 문의 유형(서비스/버그/장소 오류/기능 제안), FAQ 아코디언  
- (현재) 프론트 제출 UI — 백엔드 메일/티켓 연동은 확장 과제로 언급 가능

## 7. 시스템·데이터 아키텍처

### 기술 스택

```
[Frontend]  React (Vite) · React Router · Framer Motion
[Backend]   FastAPI · SQLAlchemy · MySQL
[AI/Search] OpenAI (채팅·아티클·임베딩) · Pinecone (벡터)
[Data]      한국관광공사 OpenAPI · 네이버 블로그 크롤(텍스트)
[Auth]      Google OAuth · JWT
```

### 아키텍처 다이어그램 (슬라이드용 ASCII)

```
┌─────────────┐     REST API      ┌──────────────────┐
│  React Web  │ ◄──────────────► │  FastAPI         │
│  갤러리·플래너 │                  │  search/chat/    │
│  마이·문의   │                  │  regions/trips   │
└─────────────┘                  └────────┬─────────┘
                                          │
                    ┌─────────────────────┼─────────────────────┐
                    ▼                     ▼                     ▼
              ┌──────────┐         ┌──────────┐         ┌─────────────┐
              │  MySQL   │         │ Pinecone │         │ OpenAI API  │
              │ places   │         │ 임베딩검색 │         │ GPT·embed   │
              │ users…   │         └──────────┘         └─────────────┘
              └──────────┘
```

### 데이터 파이프라인 (한 슬라이드)

1. **수집** — KTO API·지역 API → `places` 적재  
2. **정제** — 중복 제거, 주소·행정구역 정규화  
3. **크롤** — 블로그 본문 `crawled_texts` (요약·아티클 생성 입력)  
4. **임베딩** — `documents` + Pinecone 인덱싱  
5. **서빙** — 검색·채팅·인사이트 API

### DB 핵심 테이블 (발표용 숫자 — 실제 조회값 기준 예시)

| 테이블 | 역할 | 규모(참고) |
|--------|------|------------|
| `places` | 장소 마스터 | 약 1.2만+ |
| `crawled_texts` | 블로그 원문 | 약 3만 |
| `documents` | 임베딩 문서 | 장소별 |
| `users` / `user_scraps` / `user_trips` | 사용자·스크랩·여행 | 로그인 기능 |

> 발표 전 최신 `COUNT(*)` 한 번 더 확인해 슬라이드에 반영 권장.

## 8. 구현 하이라이트 (이번에 완성·개선한 것)

발표에서 **“우리가 실제로 구현한 것”**으로 말하기 좋은 항목:

1. **하이브리드 갤러리 검색** — 벡터 검색 + 이미지 있는 카드 우선 피드  
2. **지역별 전체 목록 vs 검색 15곳** — 탐색 UX 이원화  
3. **Trip Planner 대화형 일정** — create / refine / replace, 일차·오전·오후 스케줄  
4. **장소 비교·시각화** — ComparisonModal, TripVisualModal  
5. **GPT 아티클 v2** — JSON 구조(lead·sections) → 모달에서 읽기 좋게 렌더  
6. **플래너 상태 유지** — 로그인 시 채팅·로드맵 localStorage, 탭 전환 시 언마운트 방지  
7. **UI 통합** — PR 기반 공통 헤더·사이드바, 문의 전용 페이지, 플로팅 챗봇 제거로 UX 정리

## 10. 성과·한계·향후 계획

### 성과 (정량·정성)

- 전국 **만+ POI** 기반 웹 서비스 end-to-end 시연 가능  
- 의미 검색·채팅 일정·로드맵·스크랩·저장 **핵심 플로우** 연결  
- 공공데이터·임베딩·LLM을 **한 제품** 안에서 통합한 경험

### 한계 (솔직하게 말하면 가산점)

| 한계 | 보완 방향 |
|------|-----------|
| 문의하기 백엔드 미연동 | 이메일/Slack·관리자 대시보드 |
| 비로그인 플래너 저장 없음 | 의도적 — 계정 기반 개인화 |
| LLM·크롤 비용·지연 | 캐싱, 응답 스트리밍, 후보 수 제한 |
| 지역 데이터 편차 | 전남·전국 심화 API 추가 병합 |

### 향후 계획

- 모바일 반응형·PWA  
- 협업 여행(일정 공유)  
- 리뷰·방문 인증·상권 쿠폰 연계  
- RAG 품질 평가(검색 정확도 A/B)

## 11. 예상 Q&A

| 질문 | 답변 요지 |
|------|-----------|
| 공공데이터만 쓰나요? | KTO 중심 + 크롤 텍스트로 요약·아티클 보강 |
| 검색 정확도는? | 임베딩 + 지역 필터 + 트렌드 가중, 시연 케이스 위주 |
| LLM 환각은? | 추천 ID를 DB 장소로만 매핑, 스케줄은 규칙 기반 보정 |
| 팀 역할 분담? | *(팀원별: BE/FE/데이터/LLM — 실제 분담표로 채우기)* |
| 상용화? | 데이터 갱신·비용·CS가 관건, B2G·지자체 제휴 모델 검토 |

## 핵심 메시지 3가지 (마지막 슬라이드)

1. **공공 관광 데이터를 신뢰의 기반**으로 삼았다.  
2. **검색(발견) → 플래너(계획) → 마이페이지(보관)** 이 한 서비스 안에서 이어진다.  
3. **AI는 전부 자동이 아니라**, 일정·비교·아티클처럼 **사용자가 통제 가능한 UI**와 함께 쓴다.
