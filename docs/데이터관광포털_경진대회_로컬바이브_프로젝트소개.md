# 로컬바이브(LocalVibe) — 데이터관광포털 경진대회 프로젝트 소개

> **팀 서비스명:** 여행·지역 상권 개인 맞춤형 추천 플랫폼 **「로컬바이브」**  
> 아래 내용은 노션 등 문서에 그대로 복사해 붙여넣을 수 있도록 마크다운으로 정리했습니다.

---

## 1) 서비스 기획 배경 및 필요성

### 1. 서비스 기획 배경

- 관광 정보는 공공·민간 채널이 분산되어 있어, 여행자가 **지역별 관광지·음식·숙박·코스**를 한곳에서 비교·탐색하기 어렵습니다.
- 단순 키워드 검색만으로는 **취향·동행·일정(당일치기 등)**에 맞는 장소를 찾기 어렵고, 지역 상권 입장에서는 **방문 동기와 연결된 추천**이 부족한 경우가 많습니다.
- 이에 **한국관광공사 등 공공 관광 데이터**를 표준화해 저장하고, **의미 검색·대화형 추천**으로 개인 맞춤 경험을 제공하는 플랫폼을 기획했습니다.

### 2. 서비스 필요성

- **정보 접근성:** 공공 API로 수집한 신뢰 가능한 POI(관광지, 음식점, 숙박, 코스 등)를 한 스키마로 모아, 사용자가 지역·테마별로 빠르게 탐색할 수 있도록 합니다.
- **맞춤성:** 자연어 질의와 임베딩 기반 검색을 결합해, 사용자 표현(지역명, 분위기, 일정)에 가깝게 장소를 제안합니다.
- **지역·상권 연계:** 지역 단위 요약과 추천 업종 정보를 함께 다루어, **관광 소비가 지역 상권으로 이어지는** 탐색 흐름을 지향합니다.

---

## 2) 서비스 개요

### 1. 기획 서비스 소개(한 줄)

**전국 관광·지역 상권 정보를 통합하고, 대화·검색으로 개인에게 맞는 여행지와 코스를 추천하는 웹 기반 플랫폼입니다.**

### 2. 기획 서비스 주요 기능

- **통합 지역·장소 데이터:** 한국관광공사 국문 관광정보 등 외부 소스를 수집·정규화하여 지역 카드, 장소 메타데이터(이름, 주소, 좌표, 카테고리, 요약)로 제공합니다.
- **갤러리형 의미 검색:** 사용자 질의를 벡터화하여 유사 장소를 찾고, 트렌드·최신성·지역 필터 가중치로 재정렬하는 **하이브리드 검색**을 지향합니다.
- **대화형 여행 추천:** LLM과 내부 지역 컨텍스트를 결합해, 여행 목적·기간·지역에 맞는 추천 문장과 후보 목록을 생성합니다.
- **인증·개인화 기반(확장):** 계정 연동 등을 통해 즐겨찾기·이력 기반 추천으로 확장할 수 있는 백엔드 구조를 전제로 합니다.

### 3. 서비스 차별성

- **공공 데이터 중심의 신뢰성:** 관광지·업종 분류 등 **한국관광공사 OpenAPI** 기반 메타를 코어로 삼아, 홍보성 민간 리스트만으로 구성된 서비스와 차별화합니다.
- **검색 품질:** 키워드 일치뿐 아니라 **의미 유사도 + 트렌드·지역 가중**을 결합해, 같은 데이터셋이라도 사용자 체감 추천 품질을 높입니다.
- **데이터 파이프라인:** 수집 → 정제 → 중복 제거(이름·지역·주소 키) → DB 적재까지의 **재현 가능한 파이프라인**으로 운영·확장이 용이합니다.

### 4. (지역 특화) 서비스 내 지역 특화 관련 사항

- **전국 커버리지:** `KorService2` 기반으로 시·도 단위 및 키워드 조회를 통해 **전국 단위 관광 POI·코스**를 확보합니다.
- **지역 심화(예: 전라남도):** 공공데이터포털의 **전남 테마여행·해수욕장·지역 음식·캠핑/야영·해안마을** 등 API를 선택적으로 병합할 수 있도록 설계되어, **해안·먹거리·야외 레저** 등 남해안권 특성을 강조한 시연·서비스 확장이 가능합니다.
- **시연 시 제안:** 경진대회 발표에서는 **「전국 KTO 데이터를 주축으로, 전남권 심화 데이터로 차별 시연」**처럼 역할을 명확히 하면 심사 기준의 지역 특화 항목과도 잘 맞습니다.

## 3) 데이터 활용 방안 *(한국관광공사 OpenAPI 활용 필수)*

### 1. 활용 예정 한국관광공사 OpenAPI

- **한국관광공사 국문관광정보 서비스(KorService2)**  
  - 공공데이터포털 연계 URL 예: `https://apis.data.go.kr/B551011/KorService2`  
  - 활용(구현·계획) API 예시:
    - **지역기반 관광정보 조회** (`areaBasedList2`) — 시·군·구 코드 기반 목록 수집  
    - **키워드 검색 관광정보 조회** (`searchKeyword2`) — 키워드(도시·테마) 기반 보완 수집  
    - **공통정보 조회** (`detailCommon2`) — 개요·주소·좌표·분류 등 상세 메타 보강  

### 2. 데이터 활용 방식

- **수집:** 설정 가능한 지역 코드·키워드로 KTO API를 호출하고, 요청 간격·재시도·캐시 정책으로 **안정적 대량 수집**을 수행합니다.
- **정제·표준화:** 콘텐츠 타입 ID를 관광지·문화시설·축제·레포츠·숙박·쇼핑·음식점·여행코스 등 **내부 카테고리**로 매핑하고, 주소에서 **광역 행정구역**을 추론해 필터·통계에 활용합니다.
- **저장·검색:** 정규화된 레코드를 RDB에 적재하고, 텍스트 임베딩·벡터 DB를 활용한 **의미 기반 검색**과 연동합니다.
- **품질:** 한글 필수 여부 등 **언어·품질 필터**로 이질적인 항목을 줄이고, 외부 API 장애 시 캐시·DB 폴백으로 **서비스 연속성**을 확보합니다.

## 4) 서비스 발전 방향

### 1. 개발 서비스 향후 발전 방향

- **데이터 확장:** KTO 외 타 공공 관광·교통·축제 일정 API와의 연계, 실시간 혼잡도·날씨 등 **컨텍스트 신호** 반영.
- **추천 고도화:** 사용자 피드백(클릭·체류·저장)을 학습 신호로 쌓아, **개인화 랭킹 모델**로 진화.
- **상권·지자체 협업:** 지역 상권 데이터(매출 추정·업종 밀도 등, 제공 가능한 범위 내)와 결합한 **「관광 동선 ↔ 소비」** 인사이트 리포트.
- **접근성·다국어:** 관광공사 다국어/무장애 정보 API와 연계한 **방문객 세그먼트 확대**.
- **거버넌스:** 개인정보 최소 수집, 출처 표기, API 이용 약관 준수를 전제로 한 **지속 가능한 운영 모델** 정립.

### 기대 효과

- 여행자에게는 **탐색 비용 감소**와 **만족도 높은 맞춤 추천**, 지역에는 **데이터 기반 방문 유도**와 **상권 연계 스토리** 제시에 기여할 수 있습니다.
